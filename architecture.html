Archivist

A self-hosted, multi-user app that ingests the official data-export archives of your external accounts, normalizes every data type into one canonical Event model, and shows it all as a single searchable, filterable timeline. Every source is its own provider package. Live API pulls are part of the plan, not of the code.

1Goals & principles

  • Everything is an Event. The atomic unit is an Event — one thing that happened on a source at a time. A Reddit comment, a post, an upvote, a downvote, a saved link, a subscription, a tweet, a like, a DM, an Instagram story, a Facebook reaction — all Events, distinguished by a namespaced type (e.g. reddit.vote.down, twitter.like).
  • One timeline to rule them all. Every Event, from every source and every ingestion path, lands in the same model. The UI never needs to know how it arrived.
  • Respect all data. An export contains dozens of data types; every file and record is accounted for — mapped to a typed Event, captured as a generic Event (never hidden), or ignored with a logged reason. Each import emits a coverage report. Nothing is silently dropped.
  • Providers are isolated and pluggable. Adding a source = adding one package implementing a fixed interface.
  • Multiple accounts per source. Every Event is scoped to a connection (ACCOUNT row).
  • Raw-first, reprocess anytime. The uploaded ZIP is preserved write-once; Reprocess re-runs the current providers over it, so a better mapper reaches old imports (even promoting generic → typed) with no re-upload. built, at archive granularity
  • Per-record raw storage (raw_records) and re-normalizing from it. planned
  • Hardened by default. Tenant scoping by user_id in every port method (contract-tested), Argon2id, revocable hashed sessions, CSRF protection, rate limits, security headers, upload limits and quotas. built
  • Secrets are the crown jewels. Per-user envelope encryption, MFA, SSRF/egress controls, sandboxed providers. Nothing secret is stored today (no API keys or OAuth tokens). planned
The two ingestion realities. There's no single "download my history" REST API for most consumer accounts, so a source can be fed by (1) live API/OAuth pull planned for platforms with usable APIs (incremental, rate-limited, often paid) and/or (2) platform export bundle built — the GDPR/CCPA "download your data" ZIP, which is how you get comprehensive history and the long tail of types (likes, votes, saves, follows, seen-history) that APIs rarely expose. All 14 providers (Reddit, ChatGPT, Claude, Twitter/X, Instagram, Facebook, Google Takeout/YouTube, WhatsApp, TikTok, Telegram, Snapchat, Spotify, LinkedIn, Discord) are export-bundle providers; how to request each export is in docs/exports.md.

4The provider abstraction

A provider is a self-contained Go package under providers/<name>/. It parses one source's export and emits raw records and Events; it never touches the database, the blob store or the network. The contracts live in internal/provider (the SPI) and internal/domain (Descriptor, Event). Of the four ingestion modes only Bundle is implemented.

Split fetch from map built

Keeping Extract (read the member) separate from Normalize (map to Events) is what enables reprocessing: the original ZIP is preserved, so the current providers can be re-run over it later — including turning previously-generic records into typed Events once a mapper exists.

Registration built

internal/adapters/catalog/catalog.go lists every provider explicitly (no init() self-registration). A provider panic is recovered by the worker and fails only that import.

API / OAuth / webhook providers planned

APIPull, OAuth and Webhook modes, credential schemas, rate limits, sync cursors. No provider makes a network call today.

Subprocess plugins planned

gRPC (go-plugin) providers in a seccomp/landlock sandbox with a per-provider egress allowlist — identical interface, transparent promotion.

Respect-all-data guarantees. Every archive member is routed. Matched members produce typed Events; unmatched members are captured raw and surfaced as generic Events (type = source.unknown) so they're visible and filterable, never skipped. Every import writes a coverage report (members seen, records per type, generic-captured members, duplicates, new vs. re-imported) shown on the Import page. The preserved ZIP means adding an extractor later and pressing Reprocess re-maps old imports with no re-upload. A generic Event keeps the member's name, size, content hash and a short preview — the full bytes stay in the preserved ZIP.

Shared format adapters

  • CSV — Reddit's export is a bundle of CSVs.
  • JSON / JSONL — Meta (FB/IG) is folder-per-category JSON.
  • JS-wrapped JSON — Twitter/X data/*.js files are window.YTD.name.part0 = [ ... ]; strip prefix, parse.
  • Streaming walkers — multi-GB single-file exports (TikTok, Telegram, Snapchat, Spotify) are read token by token.
  • HTML tables — Meta's / Google's HTML export variants. Today an HTML export lands in <source>.unknown; users are told to choose JSON (docs/exports.md). planned

Encoding repair (Meta)

Facebook/Instagram JSON mis-encodes UTF-8 (bytes escaped as latin-1), producing mojibake. The Meta adapter re-encodes latin-1 → UTF-8 on read so text is stored correctly. New sources usually need only mapping logic, not parsing plumbing.

Idempotent upserts: re-importing the same or an overlapping export never duplicates events, and each import reports new vs. already-archived. Reprocess re-runs the current providers over the preserved ZIP; Delete removes an import, its archive and the events only it contributed.

planned Incremental API sync via opaque cursors; durable retries with backoff (River); a re-normalize job that rebuilds Events from stored raw records; file imports and API pulls sharing one pipeline.

8Timeline, search & filtering

  • Timeline query is keyset-paginated on (occurred_at desc, id desc), undated events last — stable at tens of millions of Events (export firehoses are large).
  • Facets: source, category, precise type, date range and free text — composable, with counts. A per-day histogram drives the overview chart. Category is the primary lever for taming high-volume types.
  • Search: PostgreSQL full-text search (tsvector, simple configuration — no stemming).
  • Media is streamed from the blob store with a sandboxing CSP.
  • Per-user Meilisearch/Typesense index; facets on connection, participants, thread, tags and target. planned
  • Per-thread conversation view and cross-source activity views built on EVENT_TARGET (targets are stored and returned with each event, but there is no view yet). planned

9Secrets — envelope encryption planned

Not implemented. There is no secrets service, KEK or DEK in the code, because there is nothing to protect yet: no API keys or OAuth tokens are stored, and export bundles carry no long-lived credential. Blob encryption at rest is not implemented either — use disk or bucket encryption. The design below is what API connectors would need.
flowchart LR
    MK["Master key (KEK): env / KMS / age, never in DB"]
    DEK["Per-user DEK: random 256-bit"]
    SEC["Secret: API key / OAuth token"]
    MK -->|wraps AES-GCM| DEK
    DEK -->|stored wrapped| DB1[("encryption_keys")]
    DEK -->|encrypts| SEC
    SEC -->|ciphertext + nonce| DB2[("secrets")]
    subgraph runtime["At sync time"]
        L1["load wrapped DEK"] --> L2["unwrap with KEK in memory"] --> L3["decrypt secret"] --> L4["use, then zeroize"]
    end
  • KEK from env / secrets manager / age key — never in the DB. Losing the DB alone doesn't expose secrets.
  • Per-user DEK stored wrapped by the KEK — scopes blast radius, enables rotation.
  • Secrets are AES-256-GCM under the DEK; decrypted in memory only during a sync, then zeroized. Never logged.
  • Export bundles carry no long-lived credential — they're uploaded files; at-rest protection is the operator's disk/bucket encryption today.

10Security & multi-tenant hardening

Tenant isolation

  • Every user-owned row carries user_id; every port method takes the user id and scopes by it.
  • Shared contract tests (internal/adapters/porttest) exercise that against the in-memory and PostgreSQL adapters.
  • Blob and staging namespaces are keyed by user id.
  • Postgres RLS as defense-in-depth (the decorative policies of 0001 were dropped in 0005). planned
  • Per-user DEKs. planned

Auth & sessions

  • Argon2id; weaker hashes are upgraded on login; dummy hash for unknown emails.
  • Opaque revocable server-side sessions, stored as SHA-256; HttpOnly SameSite=Lax cookies, Secure + __Host- on HTTPS.
  • CSRF: net/http.CrossOriginProtection (Sec-Fetch-Site / Origin), not tokens.
  • Per-IP token-bucket limits plus a per-account login throttle; signup switch.
  • TOTP MFA, WebAuthn/passkeys, OIDC, password reset by e-mail. planned

Untrusted upload handling

  • Export ZIPs are attacker-influenced: limits on entries, total and per-member bytes, JSON record size and nesting depth.
  • Members are streamed, never extracted to disk; blob keys are hashed; staging goes through os.Root.
  • Upload size cap, per-user quotas and a free-disk check before the body is read; idle timeout on uploads.
  • Resource-limited parser process, compression-ratio limit, server-side encryption of stored ZIPs. planned

HTTP edge, egress & supply chain

  • CSP, HSTS (with Secure cookies), COOP, X-Frame-Options, Permissions-Policy, nosniff; /healthz /readyz /metrics.
  • Providers make no network calls, so there is no egress to police yet.
  • Dependencies pinned by go.sum, not vendored; non-root container; make vuln runs govulncheck + npm audit by hand.
  • Per-provider egress allowlist with SSRF-blocked ranges (needed once API pulls exist). planned
  • Envelope-encrypted secrets; append-only audit log; backup tooling. planned
  • Automated govulncheck/Dependabot, SBOM, read-only container filesystem, bundled Caddy/TLS. planned
